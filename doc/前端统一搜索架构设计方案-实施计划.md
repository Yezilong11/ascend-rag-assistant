## 三、详细实施步骤

### Phase 1: 后端统一搜索服务

#### Step 1.1: 确认 ChromaImageChunkRepository.search() 方法
- 检查 `src/multimodal/infrastructure/persistence/chroma_image_chunk_repository.py` 是否已有 `search` 方法
- 如不存在，需添加 `search(query: str, top_k: int) -> List[ImageChunk]` 方法

#### Step 1.2: 创建统一搜索服务
- 新建 `src/search/` 目录
- 新建 `src/search/__init__.py`
- 新建 `src/search/unified_search_service.py`
  - 实现 `UnifiedSearchService` 类
  - 包含 `search()`, `_search_documents()`, `_search_images()` 方法
  - 并行搜索两个数据库，合并结果并按分数排序

#### Step 1.3: 扩展 API 模型
- 在 `src/rag_api/models.py` 中添加：
  - `UnifiedSearchRequest` 请求模型
  - `UnifiedSearchResult` 结果模型
  - `UnifiedSearchStats` 统计模型
  - `UnifiedSearchResponse` 响应模型

#### Step 1.4: 扩展 API 路由
- 在 `src/rag_api/routes.py` 中添加：
  - `POST /search/unified` 统一搜索路由
  - `GET /search/stats` 知识库统计路由

### Phase 2: 前端类型定义与 API 客户端

#### Step 2.1: 创建类型定义
- 新建 `frontend/src/types/search.ts`
  - `UnifiedSearchResult` 接口

  - `UnifiedSearchResponse` 接口

#### Step 2.2: 创建 API 客户端
- 新建 `frontend/src/services/unifiedSearchApi.ts`
  - `search()` 方法：调用 `POST /api/rag/search/unified`
  - 使用 `ragApiClient` 发送请求

### Phase 3: 前端搜索组件与页面

#### Step 3.1: 创建统一搜索组件

- 新建 `frontend/src/components/search/UnifiedSearchPanel.tsx`

  - 搜索结果卡片列表

#### Step 3.2: 创建搜索页面

## 五、设计原则遵循

根据文档 1.3 节的原则：

1. **数据独立性**: 不合并底层数据库，保持两个 Collection 独立维护 ✅
2. **接口统一性**: 提供统一的搜索 API，前端无需关心数据来源细节 ✅
3. **渐进式演进**: 不破坏现有功能，支持逐步迁移 ✅
4. **用户体验优先**: 搜索结果统一展示，根据内容类型自适应渲染 ✅

## 六、UI 设计规范

新组件需遵循项目现有设计风格：

- 使用 `glass-card-static` 类名作为卡片容器
- 使用 CSS 变量（`var(--neon-blue)`, `var(--bg-glass)` 等）
- 使用 Ant Design 组件（Card, Tag, Segmented 等）
- 使用 `@ant-design/icons` 图标
- 保持与现有页面一致的暗色主题风格
- 使用 `var(--transition-normal)` 过渡动画
- 使用 `var(--radius-sm)` / `var(--radius-md)` 圆角
