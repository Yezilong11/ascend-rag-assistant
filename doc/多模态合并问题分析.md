# 多模态合并问题分析文档

> 创建日期: 2026-05-08
> 目的: 分析多模态代码合并后带来的问题，为后续变更提供参考

---

## 一、问题概述

项目已完成后端多模态模块的合并（`src/multimodal/`），后端 API 路由已注册到 `server.py`，但**前端未进行相应更新**，导致多模态功能无法被用户使用。

---

## 二、具体问题分析

### 2.1 前端 API 客户端缺失

**问题描述：**
后端多模态模块在 `src/multimodal/interface/api/routes.py` 中定义了以下 API 端点：

| 端点 | 方法 | 功能 |
|------|------|------|
| `/api/multimodal/image/ingest` | POST | 上传图片并导入知识库 |
| `/api/multimodal/pdf/ingest` | POST | 上传 PDF 并导入（含内嵌图片处理） |
| `/api/multimodal/source/{source_file}` | DELETE | 删除指定来源的所有片段 |
| `/api/multimodal/status/{source_file}` | GET | 获取处理状态 |

**现状：**
- 前端 `frontend/src/services/api.ts` 仅包含三个 API 客户端：
  - `skillTreeApiClient` (`/api/skill-tree`)
  - `ragApiClient` (`/api/rag`)
  - `rssApiClient` (`/api/rss`)
- **不存在** `multimodalApiClient`

**影响：**
前端无法调用任何多模态 API。

---

### 2.2 前端类型定义缺失

**问题描述：**
后端多模态模块定义了以下 DTO：

- `ImageIngestDTO` / `ImageIngestResultDTO`
- `PDFIngestDTO` / `PDFIngestResultDTO`
- `ProcessingResult` / `ProcessingStatus`

**现状：**
- 前端 `frontend/src/types/` 目录中：
  - `rag.ts` - 仅包含文本 RAG 相关类型
  - `chat.ts` - 聊天相关类型
  - `skillTree.ts` - 技能树类型
  - **无** `multimodal.ts` 或相关类型定义

**影响：**
前端无法正确类型化多模态 API 的请求和响应。

---

### 2.3 文件上传组件功能不完整

**问题描述：**
现有 `FileUploader` 组件（`frontend/src/components/knowledge/FileUploader.tsx`）仅支持文本类文件：

```typescript
input.accept = '.pdf,.txt,.md,.doc,.docx'
```

**缺失功能：**
- 不支持图片上传（`.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`）
- 不支持多图片批量上传
- 没有 VLM 开关配置选项

**影响：**
用户无法通过界面上传图片内容到多模态知识库。

---

### 2.4 聊天输入组件不支持多模态交互

**问题描述：**
`ChatInput` 组件（`frontend/src/components/chat/ChatInput.tsx`）仅为纯文本输入：

```typescript
interface ChatInputProps {
  onSend: (message: string) => void
  // ...
}
```

**缺失功能：**
- 无法上传图片进行基于图片的问答
- 无法在提问时附加图片上下文
- 没有图片预览功能

**影响：**
用户无法像使用 GPT-4V 那样上传图片并提问。

---

### 2.5 知识库管理面板不显示多模态统计

**问题描述：**
`KnowledgeBasePanel` 组件（`frontend/src/components/knowledge/KnowledgeBasePanel.tsx`）仅显示文本知识库统计：

```typescript
interface KnowledgeBaseStats {
  document_count: number
  chunk_count: number
  status: string
}
```

**缺失功能：**
- 没有图片块数量统计
- 没有区分文本块和图片块
- 没有多模态知识库的独立管理入口

---

### 2.6 文档与代码不同步

**问题描述：**
项目架构设计文档（`doc/项目架构设计文档.md`）仍描述为 Streamlit 前端架构：

```
┌─────────────────────────────────────────────────────────────────────┐
│                   用户交互层 (Streamlit)                             │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐                │
│  │  智能问答界面 │ │  技能树管理界面│ │  知识库管理   │                │
│  └──────────────┘ └──────────────┘ └──────────────┘                │
└─────────────────────────────────────────────────────────────────────┘
```

**实际现状：**
- 项目已迁移到 React + TypeScript 前端（`frontend/` 目录）
- Streamlit 前端 (`app.py`) 已删除
- 多模态后端模块已合并

**影响：**
文档误导开发者，无法作为正确参考。

---

### 2.7 多模态与文本 RAG 职责边界模糊

**问题描述：**
后端存在两套知识库存储：

| 模块 | 存储位置 | 用途 |
|------|---------|------|
| `src/rag_api/` | ChromaDB (文本块) | 文本 RAG |
| `src/multimodal/` | ChromaDB (图片块) | 多模态 RAG |

**问题：**
- 两套系统使用同一个 ChromaDB 实例吗？
- 图片块和文本块的 metadata 如何区分？
- 查询时是否会相互干扰？

**代码证据：**
```python
# src/multimodal/infrastructure/persistence/chroma_image_chunk_repository.py
# 存在独立的 ImageChunkRepository
```

---

### 2.8 设置页面缺少多模态配置项

**问题描述：**
`SettingsPage` 中的模型选择和配置：

- `ModelSelector.tsx` - 仅配置 LLM 模型
- `RerankerConfig.tsx` - 仅配置文本重排序

**缺失配置：**
- VLM 模型开关（`vlm_enabled`）
- OCR 引擎配置
- 多模态处理偏好

## 六、总结

多模态代码合并后，后端已具备完整的多模态处理能力（OCR、VLM、PDF图片提取等），但前端完全缺失对应的：
- API 客户端
- 类型定义
- UI 组件
- 文档说明

需要进行系统性前端补全工作，才能让用户真正使用多模态功能。
