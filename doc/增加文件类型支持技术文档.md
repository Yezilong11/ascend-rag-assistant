## 1. 背景与目标

### 1.1 现状

当前系统 RAG API (`/api/rag/ingest`) 仅支持以下文件类型：

| 类型 | 扩展名 | 处理方式 |
|------|--------|---------|
| PDF | `.pdf` | `pdfplumber` 解析为 Markdown |
| 纯文本 | `.txt` | `TextLoader` 读取 |
| Markdown | `.md` | `TextLoader` 读取 |

### 1.2 目标

扩展支持以下文件类型：

| 类型 | 扩展名 | 处理方式 |
|------|--------|---------|
| Word | `.docx`, `.doc` | `UnstructuredWordDocumentLoader` |
| HTML | `.html`, `.htm` | `UnstructuredHTMLLoader` 或正则解析 |
| 图片 | `.png`, `.jpg`, `.jpeg` | `EasyOCREngine` OCR 文字提取 |
| PPT | `.ppt`, `.pptx` | `UnstructuredPowerPointLoader` |
| Excel | `.csv`, `.xls`, `.xlsx` | `UnstructuredExcelLoader` / CSV 解析 |
| JSON | `.json` | JSON 结构化文本转换 |
| JSONL | `.jsonl` | JSONL 行解析 |

### 1.3 设计原则

- **不引入新依赖**：优先使用已有 `requirements.txt` 中的库
- **复用现有架构**：不改变 `KnowledgeBase.split_document()` 的切分逻辑
- **用户体验一致**：前端上传组件 `accept` 属性与后端 `allowed_extensions` 保持同步

## 2. 文件类型支持矩阵

### 2.1 处理方式分类

| 类别 | 处理方式 | 涉及文件类型 |
|------|---------|-------------|
| A: LangChain Loader | `UnstructuredWordDocumentLoader` 等 | docx, xlsx, pptx |
| B: 纯文本转文本 | `TextLoader` 或直接读 | html, htm |
| C: CSV 解析 | 内置 csv 模块或 pandas | csv |
| D: JSON 结构化 | json 模块解析后拼接文本 | json, jsonl |
| E: OCR 提取 | `EasyOCREngine` 复用 | png, jpg, jpeg |

### 2.2 依赖检查

| 处理方式 | 依赖库 | 当前 requirements.txt 状态 |
|---------|--------|------------------------|
| UnstructuredWordDocumentLoader | `unstructured` | ✅ 已有 `unstructured>=0.18.0` |
| UnstructuredPowerPointLoader | `unstructured` | ✅ 已有 |
| UnstructuredExcelLoader | `unstructured` | ✅ 已有 |
| UnstructuredHTMLLoader | `unstructured` | ✅ 已有 |
| CSV 解析 | Python 内置 `csv` | ✅ 无需安装 |
| JSON 解析 | Python 内置 `json` | ✅ 无需安装 |
| EasyOCREngine | `easyocr` | ✅ 已有（多模态模块引入） |

**结论**：所有处理方式所需的依赖均已存在，无需新增 `requirements.txt` 条目。

## 3. 技术方案设计

### 3.1 架构图

```
用户上传文件
     │
     ▼
FastAPI routes.py
allowed_extensions 检查
     │
     ▼
KnowledgeBase.ingest()
     │
     ├── .pdf  ──────────────────► pdf_to_markdown()
     ├── .txt / .md ──────────────► TextLoader()
     ├── .docx / .doc ───────────► UnstructuredWordDocumentLoader
     ├── .html / .htm ───────────► UnstructuredHTMLLoader
     ├── .pptx / .ppt ───────────► UnstructuredPowerPointLoader
     ├── .xlsx / .xls ───────────► UnstructuredExcelLoader
     ├── .csv ───────────────────► 内置 csv.reader
     ├── .json ──────────────────► json.loads → 文本拼接
     ├── .jsonl ─────────────────► json.loads (逐行) → 文本拼接
     ├── .png / .jpg / .jpeg ────► EasyOCREngine
     │
     ▼
split_document()  ──► 向量化 ──► ChromaDB
```

### 3.2 JSON/JSONL 特殊处理设计

JSON 文件不能直接作为纯文本加载，需要展平为可读文本：

```python
# JSON 示例输入
{"title": "竞赛规则", "content": "参赛队伍不超过3人"}

# 期望输出文本
"title: 竞赛规则\ncontent: 参赛队伍不超过3人"
```

JSONL（JSON Lines）格式：每行一个 JSON 对象，逐行解析后拼接。

### 3.3 CSV 处理设计

CSV 文件转为 Markdown 表格文本：

```python
# CSV 输入
name,age,city
张三,22,北京
李四,25,上海

# 期望输出
| name | age | city |
| --- | --- | --- |
| 张三 | 22 | 北京 |
| 李四 | 25 | 上海 |
```

**改动点 4** — `KnowledgeBase` 类中新增 3 个辅助方法：

#### 4.2.1 `csv_to_markdown()` 方法

```python
def csv_to_markdown(self, csv_path: str) -> str:
    """将 CSV 文件转换为 Markdown 表格文本"""
    import csv
    lines = []
    with open(csv_path, 'r', encoding='utf-8-sig') as f:
        reader = csv.reader(f)
        for row in reader:
            lines.append("| " + " | ".join(row) + " |")
        # 添加表头分隔行
        if lines:
            separator = "| " + " | ".join(["---"] * len(lines[0].split("|") - 2)) + " |"
            lines.insert(1, separator)
    return "\n".join(lines)
```

#### 4.2.2 `json_to_text()` 方法

```python
def json_to_text(self, json_path: str) -> str:
    """将 JSON 文件展平为可读文本"""
    import json
    with open(json_path, 'r', encoding='utf-8') as f:
        obj = json.load(f)

    def flatten(obj, prefix=""):
        parts = []
        if isinstance(obj, dict):
            for k, v in obj.items():
                parts.extend(flatten(v, f"{prefix}{k}: " if prefix else f"{k}: "))
        elif isinstance(obj, list):
            for i, item in enumerate(obj):
                parts.extend(flatten(item, f"{prefix}[{i}]: "))
        else:
            parts.append(f"{prefix}{obj}")
        return parts

    return "\n".join(flatten(obj))
```

#### 4.2.3 `jsonl_to_text()` 方法

```python
def jsonl_to_text(self, jsonl_path: str) -> str:
    """将 JSONL 文件逐行解析并拼接为文本"""
    import json
    lines = []
    with open(jsonl_path, 'r', encoding='utf-8') as f:
        for line in f:
            line = line.strip()
            if line:
                obj = json.loads(line)
                text = json.dumps(obj, ensure_ascii=False)
                lines.append(text)
    return "\n".join(lines)
```

#### 4.2.4 `image_ocr_to_text()` 方法

```python
def image_ocr_to_text(self, image_path: str) -> str:
    """使用 EasyOCR 提取图片中的文字"""
    from src.multimodal.infrastructure.ocr.easyocr_engine import EasyOCREngine
    ocr = EasyOCREngine()
    text, _ = ocr.extract_text_from_image(image_path)
    return text if text else "[图片中未识别到文字]"
```

## 5. 前端适配改动

### 5.1 `frontend/src/components/knowledge/FileUploader.tsx`

当前 `input.accept`：

```typescript
input.accept = '.pdf,.txt,.md,.doc,.docx,.jpg,.jpeg,.png,.gif,.bmp'
```

**需修改为**：

```typescript
input.accept = '.pdf,.txt,.md,.doc,.docx,.html,.htm,.png,.jpg,.jpeg,.ppt,.pptx,.csv,.xls,.xlsx,.json,.jsonl'
```

注意：GIF 和 BMP 已在之前的改动中添加，但知识库 `ingest` 不处理纯图片（需通过 OCR），所以此处移除图片类型，仅保留可通过 `image_ocr_to_text()` 处理的类型。

### 5.2 文件大小限制

| 文件类型 | 建议大小限制 | 原因 |
|---------|------------|------|
| PDF, DOCX, PPTX, XLSX | 50MB | 现有限制合理 |
| JSON, JSONL | 10MB | JSON 解析内存消耗大 |
| CSV | 20MB | 大 CSV 处理慢 |
| 图片 | 10MB | OCR 处理慢 |
| HTML | 5MB | HTML 可能含大量垃圾内容 |

## 7. 风险评估

### 7.1 风险矩阵

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| `unstructured` 库对 doc/ppt/xls 解析不稳定 | 中 | 中 | 捕获异常，返回友好错误 |
| 大 JSON 文件导致内存溢出 | 低 | 高 | 文件大小限制 10MB |
| OCR 处理慢，超时 | 中 | 低 | 后台异步处理，不阻塞上传 |
| HTML 含恶意脚本 | 低 | 中 | 不执行，仅提取纯文本 |
| CSV 含特殊字符（逗号、引号） | 中 | 中 | 使用 Python csv 模块正确处理 |

### 7.2 回滚方案

如果新文件类型处理失败，系统应：
1. 捕获异常，返回结构化错误信息
2. 不影响已上传的旧文件类型
3. 前端显示具体错误原因，而非通用"上传失败"
