## 1. 总则

### 1.1 适用范围

本规范适用于昇腾AI竞赛智能助教项目的全部代码，包括：

| 层级 | 技术栈 | 目录 |
|------|--------|------|
| 后端服务 | Python 3.10+ / FastAPI | `src/`、`server.py` |
| 前端应用 | TypeScript / React 18 / Ant Design | `frontend/` |
| 配置文件 | YAML / JSON | `config/` |
| 文档 | Markdown | `doc/` |

### 1.2 核心原则

1. **一致性优先**：同一项目中，相同概念使用相同命名，相同模式使用相同实现
2. **可读性优先**：代码是给人读的，其次才是给机器执行的
3. **显式优于隐式**：类型、意图、错误处理都应显式表达
4. **最小惊讶原则**：代码行为应符合直觉，避免意外副作用

### 1.3 工具链强制执行

通过自动化工具强制执行格式规范，减少人工审查负担：

| 工具 | 用途 | 配置文件 |
|------|------|---------|
| Ruff | Python 格式化 + Lint | `pyproject.toml` |
| ESLint | TypeScript/JavaScript Lint | `frontend/.eslintrc.cjs` |
| Prettier | 前端代码格式化 | `frontend/.prettierrc` |
| EditorConfig | 编辑器统一配置 | `.editorconfig` |

## 2. 后端 Python 编码规范

### 2.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块/包名 | 全小写，下划线分隔 | `rag_engine.py`、`knowledge_base.py` |
| 类名 | PascalCase（大驼峰） | `RAGAssistant`、`KnowledgeBase`、`SkillNode` |
| 函数/方法名 | snake_case（下划线） | `similarity_search()`、`create_skill_tree()` |
| 常量 | 全大写，下划线分隔 | `PREDEFINED_MODELS`、`DEFAULT_CONFIG` |
| 私有属性/方法 | 单下划线前缀 | `_last_sources`、`_init_qa_chain()` |
| Pydantic 模型 | PascalCase + Request/Response 后缀 | `CreateSkillTreeRequest`、`ChatRequest` |
| 枚举类 | PascalCase 类名，lower_case 值 | `SkillLevel.BEGINNER` |
| 类型变量 | PascalCase | `Dict`、`List`、`Optional` |
| 配置变量 | 全大写 | `API_PORT`、`MODEL_DIR` |

**禁止事项：**

- 禁止使用单字母变量名（循环变量 `i`、`j` 除外）
- 禁止使用拼音命名
- 禁止在名字中包含类型信息（如 `name_str`、`count_int`）

### 2.2 代码格式

#### 2.2.1 缩进与换行

| 规则 | 值 |
|------|---|
| 缩进 | 4 个空格（禁止 Tab） |
| 行宽上限 | 120 字符 |
| 类之间空行 | 2 行 |
| 方法之间空行 | 1 行 |
| 函数内逻辑段落之间 | 1 行空行 |
| import 与代码之间 | 2 行空行 |

#### 2.2.2 Import 顺序

按以下分组，组间空一行，组内按字母序排列：

```python
# 1. 标准库
import os
import threading
from typing import Dict, List, Optional

# 2. 第三方库
from fastapi import APIRouter, HTTPException
from pydantic import BaseModel
import torch

# 3. 项目内部模块
from src.rag_engine import RAGAssistant
from src.knowledge_base import KnowledgeBase
from src.skill_tree.domain.models import SkillTree
```

**禁止事项：**

- 禁止使用 `from module import *`（`__init__.py` 的 `__all__` 除外）
- 禁止在文件中间插入 import

#### 2.2.3 字符串

- 使用双引号 `"` 定义字符串（与 JSON 一致）
- 多行字符串使用三引号 `"""`

```python
message = "RAG引擎初始化完成"
description = """
基于以下检索到的相关信息，回答用户的问题。
"""
```

#### 2.2.4 函数定义

- 参数过多时换行对齐：

```python
def __init__(
    self,
    knowledge_base: KnowledgeBase,
    model_key: str = "qwen2-1.5b",
    model_dir: str = "./models",
    use_reranker: bool = True,
    reranker_model: str = "bge-reranker-v2-m3",
) -> None:
```

- 类型注解必填（参数和返回值）

```python
def similarity_search(self, query: str, k: int = 3) -> List[Document]:
```

### 2.3 注释规范

#### 2.3.1 模块注释

每个 `.py` 文件顶部使用三引号文档字符串说明模块用途：

```python
"""
RAG API 路由模块
定义所有 RAG 相关的 API 端点

路由前缀: /api/rag
标签: rag

```

#### 2.3.2 类注释

```python
class RAGAssistant:
    """
    RAG智能助教核心引擎
```

#### 2.3.3 函数/方法注释

使用 Google 风格的 docstring：

```python
def query(self, question: str) -> dict:
    """
    完整问答，返回完整结果

    Args:

```

#### 2.3.4 行内注释

- 仅在代码意图不明显时添加
- 与代码同行时，至少间隔 2 个空格
- 以 `#` 加一个空格开始

```python
self.model.all_tied_weights_keys = set()  # 修复模型缺少的属性
```

### 2.4 类型注解

所有公开函数必须添加完整的类型注解：

```python
def ingest(self, file_path: str, doc_type: Optional[str] = None) -> bool:
```

Pydantic 模型字段必须标注类型：

```python
class CreateSkillTreeRequest(BaseModel):
    name: str
    description: str
```

使用 `Optional` 表示可选参数，不使用 `| None` 语法（兼容 Python 3.9）：

```python
# ✅ 正确
def detect_doc_type(self, file_path: str) -> str:

# ❌ 错误（不兼容旧版 Python）
def detect_doc_type(self, file_path: str) -> str | None:
```

### 2.5 FastAPI 特定规范

#### 2.5.1 路由定义

```python
router = APIRouter(prefix="/api/rag", tags=["rag"])
```

- `prefix` 使用 kebab-case：`/api/skill-tree`
- `tags` 使用简短英文：`["rag"]`、`["skill-tree"]`

#### 2.5.2 请求模型

- 放在 `models.py` 中定义
- 命名格式：`{动作}{资源}Request`

```python
class CreateSkillTreeRequest(BaseModel):
    name: str
    description: str

class AddSkillRequest(BaseModel):
    name: str
    description: str
    level: str
    skill_type: str
    learning_time: int = 0
```

#### 2.5.3 响应模型

- 使用 `response_model=Dict[str, Any]` 标注（当前阶段）
- 响应体统一使用 `{"success": bool, "data": ..., "message": ...}` 结构
- 后续迭代可引入 Pydantic Response Model

#### 2.5.4 依赖注入

- 放在 `dependencies.py` 中定义
- 使用 FastAPI 的 `Depends` 机制

```python
async def get_rag_assistant() -> RAGAssistant:
    ...

@router.post("/chat")
async def chat(
    request: ChatRequest,
    rag: RAGAssistant = Depends(get_rag_assistant),
):
```

#### 2.5.5 HTTP 异常

使用 `HTTPException` 抛出，状态码与业务语义对应：

```python
raise HTTPException(status_code=404, detail="技能树不存在")
raise HTTPException(status_code=400, detail="无效的技能等级或类型")
raise HTTPException(status_code=503, detail="RAG引擎未加载")
```

## 4. 前后端数据交互规范

### 4.1 统一响应结构

所有 API 响应遵循统一结构（详见 `API接口文档.md` 第 2.1 节）：

```typescript
// 成功
interface SuccessResponse<T> {
  success: true
  data: T
}

// 失败
interface ErrorResponse {
  success: false
  message: string
}

type ApiResponse<T> = SuccessResponse<T> | ErrorResponse
```

### 4.2 字段命名约定

| 层级 | 命名风格 | 示例 |
|------|---------|------|
| Python 后端 | snake_case | `skill_tree_id`、`completion_rate` |
| JSON 传输 | snake_case | `skill_tree_id`、`completion_rate` |
| TypeScript 前端 | camelCase | `skillTreeId`、`completionRate` |

**转换策略：** JSON 传输使用 snake_case，前端在 API 客户端层统一转换为 camelCase：

```typescript
// utils/transform.ts
export function toCamelCase<T>(obj: Record<string, unknown>): T {
  const result: Record<string, unknown> = {}
  for (const [key, value] of Object.entries(obj)) {
    const camelKey = key.replace(/_([a-z])/g, (_, c) => c.toUpperCase())
    result[camelKey] = value
  }
  return result as T
}
```

> **注意：** 当前阶段（V1.0），前后端统一使用 snake_case，前端不进行转换，以减少复杂度。待 V2.0 引入自动转换层后切换为前端 camelCase。

### 4.3 日期时间格式

| 场景 | 格式 | 示例 |
|------|------|------|
| 传输 | ISO 8601 | `"2026-05-02T10:30:00"` |
| 显示 | 本地化格式 | `"2026年5月2日 10:30"` |

### 4.4 空值处理

| 后端 Python | JSON 传输 | 前端 TypeScript |
|------------|----------|----------------|
| `None` | `null` | `null` |
| 空列表 `[]` | `[]` | `[]` |
| 空字典 `{}` | `{}` | `{}` |
| 不存在的字段 | 不包含该字段 | 可选属性 `field?: T` |

**规则：** 后端不应返回值为 `null` 的可选字段，而应直接省略该字段。

### 4.5 枚举值传输

枚举值以字符串形式传输，两端使用相同的字符串值：

```python
# 后端
class SkillLevel(Enum):
    BEGINNER = "beginner"
    INTERMEDIATE = "intermediate"
```

```typescript
// 前端
type SkillLevel = 'beginner' | 'intermediate' | 'advanced' | 'expert'
```

### 4.6 分页参数（预留）

当前阶段不分页。未来分页接口统一参数：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `page` | integer | 1 | 页码（从 1 开始） |
| `page_size` | integer | 20 | 每页条数（最大 100） |

分页响应结构：

```json
{
    "success": true,
    "data": {
        "items": [...],
        "total": 100,
        "page": 1,
        "page_size": 20
    }
}
```

## 5. 模块化设计原则

### 5.1 后端分层架构

```
┌─────────────────────────────────────┐
│            API 层 (routes.py)        │  ← HTTP 请求处理、参数校验
├─────────────────────────────────────┤
│         应用层 (services.py)         │  ← 业务逻辑编排
├─────────────────────────────────────┤
│         领域层 (models.py)           │  ← 核心业务模型、领域服务
├─────────────────────────────────────┤
│     基础设施层 (repositories.py)     │  ← 数据持久化、外部调用
└─────────────────────────────────────┘
```

**依赖规则：** 上层可依赖下层，下层不可依赖上层。API 层 → 应用层 → 领域层 ← 基础设施层。

### 5.3 模块间通信

| 通信方式 | 适用场景 | 示例 |
|---------|---------|------|

### 5.4 依赖注入原则

后端使用 FastAPI 的 `Depends` 机制实现依赖注入：

```python
# dependencies.py
async def get_rag_assistant() -> RAGAssistant:
    """获取 RAGAssistant 单例"""
    ...

# routes.py
@router.post("/chat")
async def chat(
    request: ChatRequest,
    rag: RAGAssistant = Depends(get_rag_assistant),
):
```

**规则：**

- 路由函数不直接实例化服务，通过 `Depends` 获取
- 单例对象（如 RAGAssistant）在 `dependencies.py` 中管理生命周期
- 每个请求创建的轻量对象（如 Service 实例）通过 `Depends` 按需创建

## 6. 错误处理规范

### 6.1 后端错误处理

#### 6.1.1 错误分类

| 错误类型 | HTTP 状态码 | 处理方式 |
|---------|-----------|---------|
| 参数校验错误 | 422 | FastAPI 自动处理 |
| 业务逻辑错误 | 400/404 | `raise HTTPException` |
| 外部依赖错误 | 503 | `raise HTTPException` + 日志 |
| 未预期异常 | 500 | 全局异常处理器 + 日志 |

#### 6.1.2 全局异常处理器

在 `middleware.py` 中注册统一异常处理器：

```python
@app.exception_handler(Exception)
async def global_exception_handler(request, exc):
    logger.error(f"未捕获异常: {exc}", exc_info=True)
    return JSONResponse(
        status_code=500,
        content={"success": False, "message": "服务器内部错误"},
    )
```

#### 6.1.3 业务错误返回

业务逻辑错误不抛异常，返回 `{"success": false, "message": "..."}`：

```python
def create_skill_tree(self, name: str, description: str) -> Dict[str, Any]:
    try:
        skill_tree = self.skill_tree_service.create_skill_tree(name, description)
        saved = self.repository.save(skill_tree)
        if saved:
            return {"success": True, "data": {...}}
        else:
            return {"success": False, "message": "创建技能树失败"}
    except Exception as e:
        logger.error(f"创建技能树时发生错误: {str(e)}")
        return {"success": False, "message": f"创建技能树失败: {str(e)}"}
```

#### 6.1.4 路由层错误转换

路由层将业务错误转换为 HTTP 异常：

```python
@router.post("/")
async def create_skill_tree(request: CreateSkillTreeRequest, ...):
    result = service.create_skill_tree(request.name, request.description)
    if not result["success"]:
        raise HTTPException(status_code=400, detail=result["message"])
    return result
```

### 6.2 前端错误处理

#### 6.2.1 API 请求错误

统一在 axios 拦截器中处理：

```typescript
ragApiClient.interceptors.response.use(
  (response) => response,
  (error: AxiosError) => {
    if (error.response?.status === 503) {
      message.error('AI引擎未加载，请先启动引擎')
    } else if (error.response?.status === 422) {
      message.error('请求参数错误')
    } else {
      message.error('网络请求失败，请稍后重试')
    }
    return Promise.reject(error)
  },
)
```

#### 6.2.2 SSE 流式错误

```typescript
// SSE 事件中检测错误
if (event === 'error') {
  const errorData = JSON.parse(data)
  message.error(errorData.message || '流式响应异常')
  setStreaming(false)
}
```

#### 6.2.3 组件错误边界

使用 React Error Boundary 包裹关键页面：

```typescript
<ErrorBoundary fallback={<ErrorFallback />}>
  <ChatPanel />
</ErrorBoundary>
```

## 7. 日志记录规范

### 7.1 后端日志

#### 7.1.1 Logger 配置

```python
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)
```

#### 7.1.2 日志级别

| 级别 | 使用场景 | 示例 |
|------|---------|------|
| DEBUG | 调试信息，仅开发环境 | `logger.debug(f"检索到 {len(docs)} 个文档")` |
| INFO | 关键业务流程 | `logger.info(f"创建技能树: name={name}")` |
| WARNING | 可恢复的异常 | `logger.warning(f"模型下载失败，回退到HuggingFace")` |
| ERROR | 需要关注的错误 | `logger.error(f"技能树保存失败: id={id}")` |
| CRITICAL | 系统不可用 | `logger.critical(f"数据库连接失败")` |

#### 7.1.3 日志格式

```
2026-05-02 10:30:00,123 [INFO] src.skill_tree.application.services: 创建技能树: name=西门子杯竞赛技能树
```

#### 7.1.4 日志规范

- 使用 `f-string` 格式化日志消息
- 包含足够的上下文信息（ID、名称、参数值）
- 异常日志使用 `exc_info=True` 记录堆栈

```python
logger.error(f"创建技能树时发生错误: {str(e)}", exc_info=True)
```

- 禁止在日志中记录敏感信息（密码、Token）

### 7.2 前端日志

#### 7.2.1 开发环境

使用 `console` 方法：

| 方法 | 场景 |
|------|------|

## 9. 版本控制策略

### 9.1 分支模型

采用简化的 Git Flow 模型：

```
main ────────────────────────────────────────
  │                                        │
  └── develop ─────────────────────────────┘
        │         │         │
        └── feat/ └── feat/ └── fix/
```

| 分支 | 用途 | 保护规则 |
|------|------|---------|
| `main` | 生产发布 | 禁止直接推送，必须通过 PR + 1 人审查 |
| `develop` | 开发集成 | 禁止直接推送，必须通过 PR |
| `feat/*` | 功能开发 | 从 `develop` 创建，合并回 `develop` |
| `fix/*` | Bug 修复 | 从 `develop` 创建，合并回 `develop` |
| `hotfix/*` | 紧急修复 | 从 `main` 创建，合并回 `main` 和 `develop` |

### 9.2 版本号规范

遵循 [语义化版本](https://semver.org/lang/zh-CN/)：

```
MAJOR.MINOR.PATCH
```

| 版本位 | 递增条件 | 示例 |
|--------|---------|------|
| MAJOR | 不兼容的 API 变更 | 1.0.0 → 2.0.0 |
| MINOR | 向后兼容的功能新增 | 1.0.0 → 1.1.0 |
| PATCH | 向后兼容的问题修复 | 1.0.0 → 1.0.1 |

### 9.3 Pull Request 规范

#### 9.3.1 PR 标题

与 Commit Message 格式一致：

```
feat(rag): 添加流式问答SSE接口
```

#### 9.3.2 PR 描述模板

```markdown
## 变更说明
简要描述本次变更的内容和目的。

## 变更类型
- [ ] 新功能 (feat)
- [ ] Bug 修复 (fix)

- [ ] 文档 (docs)

Closes #

## 测试
- [ ] 单元测试通过
- [ ] 手动测试通过
- [ ] API 接口测试通过（如有变更）

## 检查清单

- [ ] 无 console.log 残留
- [ ] 类型注解完整

```

#### 9.3.3 审查要求

| 变更类型 | 最低审查人数 | 关注点 |
|---------|------------|--------|
| 功能新增 | 1 人 | 逻辑正确性、接口兼容性、测试覆盖 |
| Bug 修复 | 1 人 | 根因分析、修复方案、回归风险 |
| 重构 | 1 人 | 行为等价性、性能影响 |
| 文档 | 可自合并 | 准确性、完整性 |
