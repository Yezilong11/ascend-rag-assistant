## 项目概述

### 项目定位

**Ascend RAG Assistant** 是一个基于**昇腾AI平台**的**RAG智能竞赛助教系统**，为参赛选手提供：

1. **智能问答服务** - 基于竞赛官方文档、规则说明进行问答，24小时答疑
2. **学习路径规划** - 技能树模块帮助整理知识体系，自动生成学习路径
3. **完全本地部署** - 所有数据都在本地，保护资料隐私

### 核心目标

- 🎯 专为昇腾AI生态优化，支持NPU加速推理
- 🚀 基于RAG检索增强生成，回答准确可靠
- 📐 模块化设计，易于扩展新功能
- 🏠 完全本地运行，无需调用第三方API

                              ↓

### 架构特点

1. **前后端分离** - Streamlit前端 + FastAPI后端，分开部署运行
2. **领域分层** - 技能树模块采用清晰的领域分层架构
3. **持久化存储** - ChromaDB存储RAG知识库，JSON文件存储技能树
4. **可扩展性** - 模块化设计，方便添加新模型、新功能

## 技术栈选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| 前端界面 | **Streamlit** | Python原生，快速构建数据应用，无需前端开发经验 |
| 后端API | **FastAPI** | 现代Python Web框架，自动生成文档，类型安全 |
| WSGI服务器 | **Uvicorn** | 高性能ASGI服务器，支持异步 |
| 向量数据库 | **ChromaDB** | 轻量级本地向量数据库，完全开源，适合本地部署 |
| RAG框架 | **LangChain** | 成熟的RAG框架，生态丰富，组件可替换 |
| 大语言模型 | **Qwen2** | 通义千问2，中文能力优秀，支持本地部署 |
| 嵌入模型 | **BGE-Large-ZH** | 中文文本嵌入最优开源模型 |
| 设备适配 | **华为昇腾NPU** | 原生支持华为昇腾910B，支持NPU推理加速 |
| 模型下载 | **ModelScope** | 阿里魔搭，国内下载速度快 |

## 模块分解

### 1. 主入口

| 文件 | 职责 |
|------|------|
| `app.py` | Streamlit前端入口，渲染问答界面和技能树界面 |
| `server.py` | FastAPI后端入口，启动技能树API服务 |

### 2. RAG核心模块 (`src/`)

| 文件 | 职责 |
|------|------|
| `knowledge_base.py` | 知识库管理：文档加载 → 文本切分 → 向量化 → 存储到Chroma |
| `rag_engine.py` | RAG引擎：检索 → 重排序 → 拼接Prompt → 调用LLM流式生成 |
| `ascend_adapter.py` | 昇腾NPU适配：设备检测、模型量化优化 |

**`knowledge_base.py` 核心职责：**
- 支持多种文档格式：PDF、TXT、Markdown
- 多种切分策略：递归字符切分、基于markdown标题切分
- 配置驱动：chunk_size、chunk_overlap可配置
- 自动初始化：程序启动自动连接数据库

**`rag_engine.py` 核心职责：**
- 支持多模型切换：Qwen2-0.5B/1.5B/ChatGLM3
- 自动下载模型：从ModelScope自动下载到本地
- 流式输出：打字机效果，改善等待体验
- 重排序：使用BGE重排序提高检索质量
- 异常处理：模型加载失败不影响系统运行

### 3. 技能树模块 (`src/skill_tree/`)

**领域驱动设计分层架构：**

```
skill_tree/
├── domain/             # 领域层 - 核心业务逻辑
│   ├── models.py       # 领域实体定义
│   └── services.py    # 领域服务
├── application/        # 应用层 - 业务协调
│   └── services.py    # 应用服务
├── infrastructure/     # 基础设施层 - 持久化
│   └── repositories.py # 仓储实现
└── api/               # 接口层 - REST API
    └── routes.py      # 路由定义
```

#### 领域层 (`domain/`)

**核心实体 (`models.py`)：**

| 实体 | 职责 |
|------|------|
| `SkillLevel` | 难度枚举：BEGINNER/INTERMEDIATE/ADVANCED/EXPERT |
| `SkillType` | 类型枚举：TECHNICAL/THEORETICAL/PRACTICAL/COMPETITION |
| `SkillRelation` | 技能关系值对象：源技能、目标技能、关系类型 |
| `LearningPath` | 学习路径：一组有序技能ID列表 |
| `SkillNode` | 技能节点：名称、描述、难度、类型、学习时间、完成率 |
| `SkillTree` | 技能树聚合根：包含多个技能节点、多个学习路径 |

**核心领域方法：**

- `SkillTree.add_skill_node()` - 添加技能节点，**自动处理根节点**（如果没有父节点自动加入根列表）
- `SkillTree.update_skill_relation()` - 更新技能关系，同时维护父子ID列表
- `SkillTree.generate_learning_paths()` - 迭代方式生成所有从根到叶的路径，**避免递归栈溢出**

**领域服务 (`services.py`)：**

- `SkillTreeService.create_skill_tree()` - 创建技能树
- `add_skill_to_tree()` - 添加技能
- `establish_skill_relation()` - 建立技能关系
- `generate_learning_paths()` - 触发生成学习路径
- `calculate_skill_tree_completion()` - 计算整体完成率

#### 应用层 (`application/`)

`SkillTreeApplicationService` 协调：
1. 从仓储加载技能树
2. 调用领域服务执行操作
3- 保存变更回仓储
4. 返回统一格式响应给API

#### 基础设施层 (`infrastructure/`)

`FileSkillTreeRepository`：
- 每个技能树保存为一个JSON文件
- 路径：`./skill_tree_data/{skill_tree_id}.json`
- 完整序列化/反序列化，包括枚举值转换

#### 接口层 (`api/`)

`routes.py` 定义REST API：

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/api/skill-tree/` | 列出所有技能树 |
| POST | `/api/skill-tree/` | 创建技能树 |
| GET | `/api/skill-tree/{id}` | 获取技能树详情 |
| DELETE | `/api/skill-tree/{id}` | 删除技能树 |
| POST | `/api/skill-tree/{id}/skills` | 添加技能 |
| POST | `/api/skill-tree/{id}/skills/relation` | 建立技能关系 |
| POST | `/api/skill-tree/{id}/paths/generate` | 生成学习路径 |

### 4. 配置

`config/config.yaml` 集中配置：

```yaml
system:
  debug: false

knowledge_base:
  persist_dir: "./chroma_db"
  embedding_model: "BAAI/bge-large-zh-v1.5"
  chunk_size: 500
  chunk_overlap: 50
  top_k: 3

llm:
  model_id: "Qwen/Qwen2-1.5B-Instruct"
  device: "auto"
  max_new_tokens: 512
  temperature: 0.7
  top_p: 0.9

ascend:
  enabled: false
  device_id: 0
  quantization: "int8"
  batch_size: 4

server:
  web_port: 8501       # Streamlit端口
  api_port: 8000       # FastAPI端口
  host: "0.0.0.0"
```

## 数据流

### 1. RAG问答数据流

```
用户输入问题
    ↓
Streamlit前端接收
    ↓
RAG引擎检索
    ↓
ChromaDB检索top_k个相关文档片段
    ↓
（可选）BGE重排序进一步优化检索结果
    ↓
拼接Prompt：<system> + 检索到的知识 + 用户问题
    ↓
LLM流式生成回答
    ↓
Streamlit逐字显示回答
    ↓
用户看到完整回答，附带参考来源
```

### 2. 创建技能树数据流

```
用户在前端填写技能树名称和描述
    ↓
前端POST请求 JSON → http://localhost:8000/api/skill-tree/
    ↓
FastAPI路由 → SkillTreeApplicationService.create_skill_tree()
    ↓
领域服务创建 SkillTree 对象
    ↓
FileSkillTreeRepository.save() → 保存为JSON文件
    ↓
返回成功响应 → 前端刷新列表
```

### 3. 添加技能 + 生成学习路径数据流

```
用户添加技能 → 建立关系
    ↓
重复N次后，点击"生成学习路径"
    ↓
POST → /api/skill-tree/{id}/paths/generate
    ↓
应用服务加载技能树 → 调用领域服务.generate_learning_paths()
    ↓
领域层：
  1. 从所有根节点开始
  2. 迭代DFS遍历所有路径
  3. 走到叶子节点生成LearningPath对象
  4. 添加到技能树中
    ↓
保存技能树 → 返回结果
    ↓
前端刷新，在"学习路径"面板展示所有路径
```

## 技术栈交互关系

### 前端 ↔ 后端交互

- **前端**：Streamlit运行在 `8501` 端口，提供完整交互界面
- **后端**：FastAPI运行在 `8000` 端口，提供技能树REST API
- **通信**：前端使用 `requests` 库调用API，JSON格式交互
- **CORS**：FastAPI配置允许所有来源跨域，方便开发

### RAG流程中的模块交互

```
用户问题
    ↓
app.py (Streamlit)
    ↓
RAGEngine (rag_engine.py)
    ↓
KnowledgeBase.retrieve() → 调用
    ↓
ChromaDB 向量检索
    ↓
返回文档列表 → RAGEngine
    ↓
（可选）重排序 → 重排序模型
    ↓
拼接Prompt → 调用 LLM
    ↓
LLM (HuggingFace pipeline) 流式生成
    ↓
streamlit 流式显示给用户
```

### 技能树分层交互

```
前端请求
    ↓
API层 (routes.py)
    ↓
应用服务层 (application/services.py)
    ↓
领域服务层 (domain/services.py)
    ↓
领域模型 (domain/models.py) 执行业务逻辑
    ↓
基础设施层 (infrastructure/repositories.py) 持久化保存
    ↓
返回响应给前端
```

**分层原则：**
- 领域层不依赖外层，业务逻辑纯Python
- 应用服务协调领域和基础设施
- 基础设施实现领域定义的接口
- API层处理HTTP请求响应

## 部署运行

### 环境要求

- Python 3.10+
- PyTorch 2.0+
- (可选) 华为昇腾NPU + CANN工具链

### 启动方式

**必须启动两个进程：**

Terminal 1 - API服务：
```bash
python server.py
```

Terminal 2 - 前端：
```bash
streamlit run app.py
```

**Windows一键启动：**
```bash
start.bat
```

### 端口映射

| 服务 | 默认端口 | 用途 |
|------|---------|------|
| Streamlit | 8501 | 前端用户界面 |
| FastAPI | 8000 | 技能树API |

修改端口：编辑 `config/config.yaml` → `server` 段落

### 开发模式

开发时需要重新启动对应的进程：
- 修改前端 → 保存后Streamlit自动刷新
- 修改API → 需要重启 `python server.py`

## 开发指南

### 添加新功能

#### 1. 给技能树模块添加新API

1. 在 `domain/models.py` 添加新实体（如果需要）
2. 在 `domain/services.py` 添加领域方法
3. 在 `application/services.py` 添加应用方法
4. 在 `api/routes.py` 添加路由
5. 在 `app.py` 添加前端调用代码

#### 2. 添加新的大模型

1. 在 `rag_engine.py` 的 `PREDEFINED_MODELS` 添加模型配置
2. 在前端下拉框自动会出现，用户可以选择

#### 3. 修改文本切分策略

修改 `src/knowledge_base.py` → `split_documents()` 方法

### 常见问题

#### Q: 端口冲突怎么办？

A: 修改 `config/config.yaml` 中的 `server.web_port` 或 `server.api_port`

#### Q: OMP: Error #15: 初始化错误怎么办？

A: 这是Windows上PyTorch的常见问题，设置环境变量解决：
```bash
set KMP_DUPLICATE_LIB_OK=TRUE
```
`start.bat` 已经包含这个设置。

#### Q: 技能树生成不了路径怎么办？

A: 参见 `技能树模块使用说明.md` → 常见问题，必须有至少一个根技能（没有前置依赖）

#### Q: 数据存在哪里？

A:
- RAG知识库：`./chroma_db/`
- 技能树数据：`./skill_tree_data/`
- 模型文件：`./models/`
