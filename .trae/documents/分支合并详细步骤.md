# 分支合并详细步骤指南

## 📋 合并前准备

### 第一阶段：清理当前分支（feature/front_back）

在进行分支合并之前，先清理当前分支中的冗余文件，避免合并时产生冲突。

#### 步骤 1.1：删除旧 Streamlit 前端

**目标**：删除 `app.py`，避免与 React 前端冲突

```bash
# 在 feature/front_back 分支上执行
git rm app.py
```

**验证**：
```bash
git status
# 确认 app.py 不再出现在 "Changes to be committed" 中
```

---

#### 步骤 1.2：删除冗余的前端演示目录

**目标**：删除 `frontend-demo/`，保留功能更完整的 `frontend/`

```bash
git rm -r frontend-demo/
```

**验证**：
```bash
ls -la
# 确认只剩下 frontend/ 目录，没有 frontend-demo/
```

---

#### 步骤 1.3：删除空文件

**目标**：删除 `crawler.py`（空文件）

```bash
git rm crawler.py
```

---

#### 步骤 1.4：合并 Ascend Adapter 文件（可选）

**目标**：将 `ascend_adapter_temporary.py` 的功能合并到 `ascend_adapter.py`

**操作**：
1. 打开 `src/ascend_adapter.py`
2. 用 `src/ascend_adapter_temporary.py` 的内容替换它
3. 然后删除临时文件：
```bash
git rm src/ascend_adapter_temporary.py
```

---

#### 步骤 1.5：提交清理更改

```bash
git add -A
git commit -m "chore: 清理冗余文件，为分支合并做准备

- 删除旧 Streamlit 前端 (app.py)
- 删除冗余前端演示目录 (frontend-demo/)
- 删除空爬虫文件 (crawler.py)
- 合并 Ascend Adapter 到统一文件"
```

---

### 第二阶段：执行分支合并

假设你要将 `feature/10` 的某些内容合并到当前分支，或进行双向合并。

#### 场景 A：合并 feature/10 到当前分支 (feature/front_back)

如果你想保留 `feature/10` 中某些有用的更改（如特定的竞赛数据）：

```bash
# 1. 确保在当前分支
git checkout feature/front_back

# 2. 获取最新远程分支信息
git fetch origin

# 3. 查看两个分支的差异，决定要合并什么
git log --oneline feature/10..origin/feature/front_back
git log --oneline origin/feature/front_back..feature/10

# 4. 执行合并（只合并选定的文件，避免冲突）
git checkout feature/10 -- data/某些有用的数据目录
git checkout feature/10 --某个有用的配置文件

# 5. 或者直接合并（如果有兼容的更改）
git merge feature/10
```

---

#### 场景 B：变基合并（Rebase）- 推荐

如果你想保持线性历史，更清晰：

```bash
# 1. 切换到 feature/10 分支
git checkout feature/10

# 2. 变基到最新代码
git rebase origin/feature/front_back

# 3. 如果有冲突，解决冲突后：
git add .
git rebase --continue

# 4. 切换回主分支，合并变基后的分支
git checkout feature/front_back
git merge feature/10
```

---

#### 场景 C：Squash 合并

如果 `feature/10` 有很多零散的提交，想合并为一个干净的提交：

```bash
# 1. 切换到 feature/10 分支
git checkout feature/10

# 2. 变基并压缩提交
git rebase -i origin/feature/front_back

# 3. 在编辑器中，将除了第一个之外的所有 "pick" 改为 "squash"
# 保存退出

# 4. 切换回主分支，执行合并
git checkout feature/front_back
git merge --squash feature/10

# 5. 提交合并
git commit -m "feat: 合并 feature/10 的所有更改"
```

### 第三阶段：解决合并冲突

#### 步骤 3.1：识别冲突文件

```bash
git status
# 标记为 "Unmerged" 的文件就是有冲突的文件
```

#### 步骤 3.2：查看冲突内容

```bash
git diff
# 或打开冲突文件查看
```

冲突标记格式：
```
<<<<<<< HEAD
当前分支的内容
=======
被合并分支的内容
>>>>>>> feature/10
```

#### 步骤 3.3：手动解决冲突

编辑冲突文件，选择保留：
- 只保留 HEAD（当前分支）
- 只保留 feature/10
- 或者手动合并两者的有用部分

#### 步骤 3.4：标记冲突已解决

```bash
git add <冲突文件>
git add .  # 添加所有解决的冲突
```

#### 步骤 3.5：完成合并提交

```bash
git commit -m "merge: 解决冲突，完成分支合并"
```

---

### 第四阶段：验证合并结果

#### 步骤 4.1：功能验证

```bash
# 启动后端服务
python server.py &
python rag_server.py &

# 启动前端（另一个终端）
cd frontend
npm install
npm run dev
```

#### 步骤 4.2：检查关键文件

确认以下文件状态正确：

```bash
# 应该存在
ls frontend/
ls src/rag_api/
ls server.py
ls rag_server.py

# 应该不存在（已删除）
ls app.py           # 应该报错，不存在
ls frontend-demo/   # 应该报错，不存在
ls crawler.py       # 应该报错，不存在
```

## 🎯 推荐的最佳合并流程

### 方案：GitHub PR/MR 合并（最安全）

1. **推送当前分支到远程**
```bash
git push origin feature/front_back
```

2. **在 GitHub/Gitea 上创建 Pull Request**
   - Base: `feature/front_back`
   - Compare: `feature/10`

3. **在 PR 页面检查变更**
   - 确认没有不必要的文件
   - 逐个检查冲突

4. **通过 PR 合并**

## 📝 快速执行清单

### 一键清理命令

```bash
# 在 feature/front_back 分支上执行
git rm app.py && \
git rm -r frontend-demo/ && \
git rm crawler.py && \
git add -A && \
git commit -m "chore: 清理冗余文件"
```

### 一键合并命令（假设无冲突）

```bash
git merge feature/10 --no-edit
```

---

## ⚠️ 注意事项

1. **合并前务必备份**：在做重大变更前，创建备份分支
   ```bash
   git branch backup-before-merge
   ```

2. **不要强制推送公共分支**：如果已经推送了远程，避免使用 `git push --force`

3. **测试环境验证**：合并后先在本地测试，不要直接推送到生产环境

4. **文档更新**：如果 `app.py` 或 `frontend-demo/` 中有文档引用，记得更新

## 🔧 如果你需要帮助

如果合并过程中遇到问题，可以：

1. 查看详细错误信息：
   ```bash
   git status
   git diff --stat
   ```

2. 取消合并（未完成时）：
   ```bash
   git merge --abort
   ```

3. 寻求帮助时，请提供：
   - `git status` 输出
   - 冲突文件的完整内容
   - 你期望的结果
