# 国际大学生程序设计竞赛（ICPC） - 评分标准

**来源网址**: https://icpc.global/
**信息整理时间**: 2026-03-15

## 一、竞赛简介

国际大学生程序设计竞赛（International Collegiate Programming Contest，简称ICPC）是由ICPC基金会（ICPC Foundation）主办的全球最具影响力的大学生程序设计竞赛[citation:1][citation:8]。该竞赛的历史可以追溯到1970年，最初由美国德克萨斯A&M大学举办，1977年在ACM计算机科学会议期间举办了首次总决赛，并逐渐演变为一年一度的国际性赛事[citation:1]。由于美国计算机协会（ACM）曾长期赞助该竞赛，因此许多人习惯称之为“ACM竞赛”或“ACM-ICPC”[citation:1][citation:8][citation:9]。

**竞赛宗旨**：旨在展示大学生的创新能力、团队精神和在压力下编写程序、分析和解决问题的能力[citation:1]。

**竞赛规模**：经过近50年的发展，ICPC已经发展成为全球最具影响力的大学生程序设计竞赛。以2015年为例，总共有来自560所大学的840支队伍参加比赛，而到了2004年，这一数字迅速增加到840所大学的4109支队伍，并以每年10-20%的速度增长[citation:1]。

**赛事构成**：ICPC赛事由各大洲区域预赛（Regional）和全球总决赛（World Finals）两个阶段组成[citation:1][citation:8]。区域预赛一般安排在上一年的9-12月举行，而总决赛则安排在每年的3-5月举行[citation:8][citation:9]。

## 二、参赛要求

### 2.1 参赛资格与组队

| 要求类型 | 具体规定 |
|:---:|:---|
| **参赛对象** | 各高校在校注册大学生 |
| **组队人数** | 每队由**至多3名队员**组成 |
| **年龄限制** | 有一定的年龄限制（具体以当年规则为准） |
| **参赛限制** | 每位队员每年最多可以参加2站区域选拔赛[citation:1] |
| **代表学校** | 以团队的形式代表各学校参赛 |

### 2.2 比赛环境

| 项目 | 具体要求 |
|:---:|:---|
| **比赛时长** | **5个小时** |
| **题目数量** | 7到13个问题[citation:1][citation:8] |
| **编程语言** | C、C++、Java、Python等[citation:1][citation:2] |
| **机器配置** | 每队使用**1台电脑**[citation:1] |
| **携带资料** | 可携带任何非电子类资料，包括书籍和打印出来的程序等[citation:1] |

## 三、竞赛形式

### 3.1 比赛流程

| 阶段 | 时间 | 特点 |
|:---:|:---:|:---|
| **比赛全程** | 5小时 | 实时评测并返回结果[citation:1][citation:6] |
| **前4小时** | 第1-4小时 | 可实时看到排名[citation:1] |
| **封榜** | 最后1小时 | 封榜期间无法看到其他队伍的提交结果，以保留悬念[citation:1][citation:6][citation:9] |

### 3.2 气球奖励机制

比赛中有一个有趣的传统：每队在正确完成一道题后，组织者会在其位置上升起一只代表该题颜色的气球。每道题目第一支解决掉它的队伍还会额外获得一个“FIRST PROBLEM SOLVED”的气球[citation:1]。

## 四、评分标准

### 4.1 排名核心原则

ICPC的排名采用**两要素排序法**：

| 优先级 | 排序依据 | 说明 |
|:---:|:---:|:---|
| **第一优先级** | 正确解题数量 | 解出问题越多的队伍，排名越靠前 |
| **第二优先级** | 总用时（罚时） | 解出问题数相同时，总用时越少的队伍排名越靠前 |

*总用时为每个解决了的问题所用时间之和[citation:1][citation:4][citation:6]。*

### 4.2 单题用时计算公式

对于每一道**正确解答**的题目，其贡献的用时计算公式如下：

| 项目 | 说明 |
|:---:|:---|
| **通过时间** | 从竞赛开始到该题**第一次正确提交**所经过的时间（分钟） |
| **错误提交罚时** | 在该题第一次正确提交之前的每一次错误提交，加罚**20分钟**[citation:1][citation:2][citation:4] |
| **单题用时** | **通过时间 + 错误提交次数 × 20分钟** |

**特别说明**：
- 未正确解答的题目**不记时**，也不计入总用时[citation:1][citation:4]。
- 错误提交次数统计的是第一次正确提交之前的所有提交，编译错误（Compile Error）通常不计入罚时[citation:6]。

### 4.3 总用时计算公式

**队伍总用时 = Σ(每道正确解答题目的用时)**

其中：
- Σ表示对所有正确解答的题目求和
- 每道正确解答题目的用时 = 该题通过时间 + (该题第一次通过前的错误提交次数 × 20分钟)

### 4.4 示例说明

假设A、B两队都正确完成两道题目，具体数据如下：

| 队伍 | 题目1通过时间 | 题目1错误次数 | 题目2通过时间 | 题目2错误次数 | 总用时计算 |
|:---:|:---:|:---:|:---:|:---:|:---|
| **A队** | 1:00 (60分钟) | 0 | 2:45 (165分钟) | 0 | 60 + 165 = **225分钟** |
| **B队** | 1:20 (80分钟) | 1 | 2:00 (120分钟) | 0 | (80+20) + 120 = **220分钟** |

**结果**：虽然两队解题数相同，但B队总用时220分钟 < A队225分钟，因此**B队获胜**[citation:1]。

### 4.5 评判结果类型

提交程序后，评测系统会返回以下结果之一[citation:1][citation:6]：

| 缩写 | 英文 | 中文含义 |
|:---:|:---|:---|
| **AC** | Accepted | 通过！答案正确 |
| **WA** | Wrong Answer | 答案错误 |
| **RTE** | RunTime Error | 程序运行出错，意外终止 |
| **TLE** | Time Limit Exceeded | 超时，程序未在规定时间内出答案 |
| **PE** | Presentation Error | 格式错误，未按规定格式输出 |
| **MLE** | Memory Limit Exceeded | 超内存，程序超出规定空间 |
| **CE** | Compile Error | 编译错误，程序编译不过 |

## 六、评审特点分析

1. **双要素排序法**：ICPC排名采用“解题数优先，罚时次之”的排序原则。解题数越多排名越靠前；解题数相同时，总用时（罚时）越少排名越靠前[citation:1][citation:4][citation:6]。

2. **罚时机制**：每道题在第一次正确提交之前的每一次错误提交，都会加罚20分钟。这一机制惩罚了盲目提交的行为，鼓励参赛者在提交前进行充分测试[citation:1][citation:2][citation:5]。

3. **封榜规则**：比赛结束前一小时封榜，期间无法看到其他队伍的提交结果，保留悬念[citation:1][citation:6][citation:9]。封榜后的提交会在榜单上用黄色标记表示尝试次数，但具体结果未知[citation:6]。

4. **团队协作考核**：3人使用1台电脑，不仅考察个人编程能力，更考验团队协作、分工配合和沟通能力[citation:1]。

5. **压力测试**：5小时连续作战，考察选手在时间压力下的心理素质和持久专注力[citation:1][citation:2][citation:5]。

6. **实时反馈**：每道题提交后会立即得到评测结果（AC/WA等），让选手能够及时调整策略[citation:1][citation:6]。

7. **原创性要求**：竞赛强调参赛者自主完成题目，禁止抄袭和作弊行为。

8. **国际化标准**：试题描述为英文，全球统一标准，考验选手的专业英语阅读能力[citation:1]。
